- [Run presentation layer](run-presentation.md) — value-tiered XP gems, `EnemyDef.sizeClass` as a render-only scale hook, `arachnidRig`/`serpentRig` built by reusing existing limb `PartKey`s instead of adding new ones; hazard-kind weapons place `count` nodes in a linked ring, `bonusVsStatusId`/`bonusVsStatusMult` is a reusable elemental-combo hook, `'meteor'` telegraphs then strikes from off-screen, `CharacterDef.stormCloud` is a draggable auto-cycling companion (new `PointerMode: 'cloud'`) that a follow-up pass gave manual mode control (`setStormCloudMode`, permanently overriding auto-cycle), a fourth `frost-rain` mode, and ground painting on the pre-existing `FluidTile` system (`fire-storm`/`acid-storm`/`frost` stains that outlive the cloud and refresh on repaint, washable by `water`); and: grep the roster for a theme or archetype's keywords before authoring new "themed" content, or you'll duplicate an existing palette/status-effect/lore niche.
- [Crew feature](crew-feature.md) — `RESCUE_ROUTE_BY_AREA` only needs an entry for areas granting more than one ally across replays (single-ally areas use just `AreaDef.rescueAllyId`); every `HubRoomDef` needs both a resident ally and activities scoped to that `roomId` or `rollCrewActivities()` silently has nothing to offer; `AllyDef.rigHint` maps an ally onto an existing `humanoidRig()` silhouette option instead of hardcoding rig choices by id.
